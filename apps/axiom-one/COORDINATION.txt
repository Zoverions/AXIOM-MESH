# AXIOM One coordination adapter (experimental)

This app-local module prepares a read-only mesh status view. It does not connect to the live relay, serve a browser route, grant a role, or make an agent available. The current authenticated Gateway `status.get` has no fleet heartbeat or lease data. The separate Social feed contract remains a design-only mock.

## Source contract and provenance

`adaptMeshStatusV1()` accepts Cosmo's `MESH_STATUS v1` shape: an `updated_at` timestamp and an `agents` object keyed by agent ID. Agent entries may report `state`, `enc`, `heartbeat_slot`, `last_heartbeat`, `lease`, `work`, `blockers`, and `last_processed_id`. The received sample is operational data and is **not committed** as a fixture. Tests use synthetic agents in the same shape.

The adapter produces `axiom-one.mesh-observation.v1` for `deriveCoordinationView()`. Its second argument is provenance supplied by the trusted transport: source ID, audience ID, monotonic revision, and SHA-256 content digest. It normalizes timestamps to UTC, bounds text and list sizes, and treats human prose as a report rather than proof. `g2-verified` remains `reported_encryption`, never an attested verification; a prose lease has no verified expiry and remains `unknown`. A missing heartbeat, sequence watermark, or processed timestamp remains unknown. The v1 sample has no event history, capacity metrics, or resource metrics; those are empty or unknown. Do not infer a stalled worker from an unchanged `last_processed_id` alone.

The derived view includes a source state (`live`, `stale`, `unavailable`, `malformed`, or `replayed`), an `as_of` timestamp, agent states, and bounded event metadata. A failed fetch may retain the last good observation only with an unmistakable unavailable state, matching source and audience, and at most 24 hours old. A lower revision, older timestamp, or changed content at an equal revision cannot replace a newer observation. A source older than 35 minutes is stale, matching the currently reported `:00/:30` publication rhythm with a small grace period. These are display policies for a future endpoint, not proof that any agent is online.

## Authentication and activation dependency

Only a trusted server may call the derivation function with a verified `scope`. Owner scope sees all agents and known resource/checkpoint fields; other scopes must provide an explicit agent allowlist. Work and blockers are hidden from members and require explicit field scope even for coordinators. Browser input must never choose or widen that scope. The prospective node-2 loopback source requires a documented principal and role contract, monotonic provenance, and server-side access checks. Tokens stay out of URLs, browser storage, public JSON, logs, and the committed repository. The existing preview continues to bind only to `127.0.0.1`, use memory-only browser tokens, and make no live-coordination claim.

`readMeshStatus()` is an unwired server-side reader for the future source. It accepts only an exact IPv4 loopback HTTP origin with no URL credentials, query, or fragment; follows no redirects; opens a distinct coordinator-issued feed token file without following symlinks, then validates and reads from that same descriptor (owner and mode 0600); caps the JSON response at 64 KiB; and uses a five-second timeout. A 401/403 fails closed. It accepts a decimal `x-mesh-revision` integer; absent that header, it provisionally uses the feed's `updated_at` milliseconds as a display revision. It hashes the exact response bytes for equal-revision conflict detection. The fallback is not a cryptographic anti-replay guarantee. The trusted server must retain source/audience revision high-water metadata independently of the last-good display cache. Gateway login remains separate from the feed-source credential. No browser route calls this reader yet because principal and role binding are not specified.

No public navigation, production service, DNS, or authority kernel is changed here. Connecting the transport and authenticated view is a separate step once its endpoint and unified-login behavior are specified and tested.
