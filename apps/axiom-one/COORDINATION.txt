# AXIOM One coordination adapter (experimental)

This app-local module prepares a read-only mesh status view. It does not connect to the live relay, serve a browser route, grant a role, or make an agent available. The current authenticated Gateway `status.get` has no fleet heartbeat or lease data. The separate Social feed contract remains a design-only mock.

## Source contract and provenance

`adaptMeshStatusV1()` accepts Cosmo's `MESH_STATUS v1` shape: an optional `updated_at` timestamp (ISO-8601 preferred; a JSON number of milliseconds since the Unix epoch is also accepted) and an `agents` object keyed by agent ID. Agent entries may report `state`, `enc`, `heartbeat_slot`, `last_heartbeat`, `lease`, `work`, `blockers`, and `last_processed_id`. Optional structured v1 fields are `lease_expiry` (ISO timestamp or null), `checkpoint_high_water` (opaque string), and `resources` (object) per agent, plus a bounded top-level `history` array of `{ts,event,actor}`. Cosmo confirmed this field placement. The received sample is operational data and is **not committed** as a fixture. Tests use synthetic agents in the same shape.

The adapter produces `axiom-one.mesh-observation.v1` for `deriveCoordinationView()`. Its second argument is provenance supplied by the trusted transport: source ID, audience ID, revision kind and value, and SHA-256 content digest. It normalizes timestamps to UTC, bounds text and list sizes, and treats human prose as a report rather than proof. `g2-verified` remains `reported_encryption`, never an attested verification; a future structured expiry alone does not establish an active lease. A missing heartbeat, sequence watermark, or processed timestamp remains unknown. The opaque high-water ID cannot be compared numerically with `last_processed_id`. Optional resource keys are allowlisted; history text is scoped to owners, and events without a known agent actor are omitted. Do not infer a stalled worker from an unchanged `last_processed_id` alone.

The derived view includes a source state (`live`, `stale`, `unavailable`, `malformed`, `replayed`, or `unversioned`), an `as_of` timestamp when known, agent states, and bounded event metadata. A failed fetch may retain the last good observation only with an unmistakable unavailable state, matching source and audience, and at most 24 hours old. A lower revision, older timestamp, or changed content at an equal revision cannot replace a newer observation. A source older than 35 minutes is stale, matching the currently reported `:00/:30` publication rhythm with a small grace period. Without a revision or update time the data is readable with an explicit `unversioned` state, never a live or healthy assertion. These are display policies for a future endpoint, not proof that any agent is online.

## Authentication and activation dependency

Only a trusted server may call the derivation function with a verified `scope`. Owner scope sees all agents and known resource/checkpoint fields; other scopes must provide an explicit agent allowlist. Work and blockers are hidden from members and require explicit field scope even for coordinators. Browser input must never choose or widen that scope. Cosmo's forthcoming unified login contract binds a presented credential to a principal in the authority registry and returns server-enforced role and capabilities; it is not implemented here. The prospective node-2 loopback source requires that role contract, server-side access checks, and replay high-water tracking. Tokens stay out of URLs, browser storage, public JSON, logs, and the committed repository. The existing preview continues to bind only to `127.0.0.1`, use memory-only browser tokens, and make no live-coordination claim.

`readMeshStatus()` is an unwired server-side reader for the future source. `MESH_STATUS_URL` configures the source and `MESH_STATUS_BEARER` supplies a distinct coordinator-issued, read-only feed credential to the server process; a protected `tokenFile` is supported and preferred where available. It accepts only an exact IPv4 loopback HTTP origin with no URL credentials, query, or fragment; follows no redirects; validates and reads a token file from one descriptor without following symlinks (owner and mode 0600); caps the JSON response at 64 KiB; and uses a five-second timeout. A 401/403 fails closed. The source-issued decimal `x-mesh-revision` integer takes precedence. Without the header, a valid ISO or numeric epoch-millisecond `updated_at` becomes the same provisional timestamp revision; without either, the feed is flagged unversioned. A present malformed update time fails closed, while an absent one remains unversioned. Numeric values must be safe nonnegative integers within the four-digit UTC year range; numeric strings are not accepted. It hashes the exact response bytes for equal-revision conflict detection. A timestamp fallback is not a cryptographic anti-replay guarantee, and unversioned data cannot establish freshness. The trusted server must retain source/audience revision high-water metadata independently of the last-good display cache. Gateway login remains separate from the feed-source credential. No browser route calls this reader yet because principal and role binding are not specified.

No public navigation, production service, DNS, or authority kernel is changed here. Connecting the transport and authenticated view is a separate step once its endpoint and unified-login behavior are specified and tested.
