## Version boundary

`0.12.0-dev.3` is the active development line after immutable candidate `v0.11.0`. These notes distinguish registry-backed implemented capabilities from built safety/productization primitives that remain unavailable or production-unreachable.

The current line combines the hardened four-service authority/evidence kernel; constrained machine principals; Grid continuity anchors; AXIOM One/local-social foundations; governed Axiom Education foundations; a production-unreachable repository draft-PR effect chain; Agent Runtime Adapter v1; non-mutating Linux host planning; and signed install-release input/artifact verification.

None of those statements is a production-promotion claim.

## Install and release productization

The source-checkout setup remains distinct from fresh-host installation.

### Non-mutating host planner

`personal-local` and `infrastructure-node` remain `specified` install targets. The current planner can observe or accept host facts and produce deterministic digest-bound installation plans, but it reports no host mutation, no credential creation, no live services, no network effect, and no installation authority.

### Signed install-release manifest verifier

The development line now defines and verifies:

- `axiom-install-release-manifest-package.v1`;
- `axiom-install-release-manifest.v1`;
- `axiom-install-release-manifest-policy.v1`.

Trust is external to the signed package. Verification requires an active Ed25519 signer supplied by the verifier/operator with role `release-installer-authority`; the package cannot self-trust by embedding a public key.

The signed manifest binds exact source revision, kernel/channel, install-profile target statuses, current Node/npm requirements, current migration generation/rollback mode, current install/capability/application/network/source-setup control-plane digests, artifact SHA-256/byte-length metadata, documentation bundle, SBOM, provenance, validity window, and explicit non-claims.

Artifact bytes are verified independently from manifest metadata. A successful manifest verification still reports:

- `artifact_bytes_verified: false` until bytes are checked;
- `host_mutation_authorized: false`;
- `installation_authority_granted: false`;
- `mesh_authority_granted: false`;
- `network_authority_granted: false`;
- `node_enrolled: false`;
- `services_started: false`.

This verifier closes release-input authenticity/compatibility; it does **not** implement the privileged clean-machine installer or publish a production release-signing key.

### AXIOM Host continuity

Retained H0/H1 AXIOM Host research explored an image-built Linux appliance with UEFI-oriented boot, dm-verity/read-only root, separate durable state, artifact inventories, secret scanning, and image diagnostics. It is hundreds of commits behind current code and is not merged wholesale.

The signed-manifest contract reserves `axiom-host-image` as an installable artifact class. Signing and hashing such an image establishes approved byte identity only; it does not establish Secure Boot, measured boot, TPM attestation, encrypted mutable state, firmware correctness, or remote attestation.

The nominal historical H2 update/rollback branch did not advance beyond the H0/H1 head, so real update/rollback work remains a current productization task.

## Axiom Education convergence

[Axiom Education](https://github.com/Zoverions/Axiom-Education) remains a first-class AXIOM application with an independent release lifecycle. The current Mesh contains governed learner memory/record ownership, consent-bound append/read foundations, provider contracts, Sandbox composition, Grid route registration, and Hypervisor-mediated learner self-read without direct Sandbox-to-Grid authority.

The separate Education repository has its own compatibility/adoption evidence boundary. Installing, listing, or verifying an Education release does not grant curriculum, provider, school, institution, educator/guardian, learner-record, network, or production authority.

## Grid continuity clarification

Local Grid verification detects invalid signatures, altered records, gaps, broken links, and disagreement with local head/checkpoint state. Local state alone cannot prove absence of a consistently removed suffix if matching local metadata is rewritten.

`axiom-grid-continuity-anchor.v1`, retained outside `AXIOM_DATA_DIR` and checked against the full chain from genesis, provides the stronger truncation boundary. A valid anchor proves the current history equals or extends the retained head **through the newest retained anchor**. It does not cover later unanchored events and does not remove malicious-host/root or active Grid-signing-key compromise from the trust assumptions.

Grid remains a single transparency log rather than replicated BFT consensus.

## Built repository-effect prototype — production-unreachable

The current source includes an evidence-first repository-document proposal/effect prototype that remains **production-unreachable**.

Its built path covers signed read-only planning, resolver eligibility/admission/review, exact target policy, confirmation/independent approval, and durable one-use preparation. The state transition records `approval.consumed` before the separately bound `external.effect.prepared` state.

The external-effect outbox refuses to fabricate success under uncertainty. The credential-isolated docs-only GitHub repository operator independently verifies durable Grid preparation before GitHub I/O and can create or recover an **open draft pull request** on a deterministic effect branch.

It has **no merge authority** and reports `merge_performed: false` and `base_branch_content_changed: false`.

Production reachability remains closed because `mesh/config/intent-remediation-executors.json` has zero mappings, production policy has no `repository.docs.pull-request.create`, and no supported runtime route invokes the chain. Signed release/install metadata does not change that fact.

## Agent Runtime Adapter v1

Agent Runtime Adapter v1 remains a byte-pinned contract with synthetic reference conformance. It covers grant translation, bounded tool/capability mapping, credential references, lifecycle, cancellation, revocation, idempotency, fallback, uncertainty, signed receipts, and rollback.

The reference loads **no external runtime**, resolves no production runtime credential, performs no external effect, and does **not certify** OpenClaw, Hermes, Agent Zero, MCP, A2A, or another external runtime.

External runtimes remain clients of:

```text
Gateway -> Hypervisor -> Sandbox -> Grid
```

## AXIOM One state

AXIOM One remains an experimental loopback-only browser/PWA preview. It provides bounded status/review, owner-private memory and directional provenance, confirmation-bound tombstoning, selective export/reveal, raw evidence, approval-state distinctions, uncertainty recovery, and local social presentation foundations.

It is not a supported end-user release and still lacks the full browser-session/device security, accessibility/usability evidence, signed packaging, restore/bulk-ingestion, hard deletion, and general consequential plan/execute surfaces required for promotion.

## Documentation synchronization

The development line now includes a machine-readable documentation-impact policy evaluated from the exact pull-request base/head diff inside `npm run check` on protected PR verification.

The initial governed surfaces cover host installation, signed release/install trust, Education-consumed Mesh contracts, service-network policy, capability status/evidence bindings, application catalogue changes, and the documentation-impact policy itself.

This does not claim perfect semantic documentation generation. It creates a fail-closed requirement that high-risk implementation/configuration changes move with their named documentation families.
