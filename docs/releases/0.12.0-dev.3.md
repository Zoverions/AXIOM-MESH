# AXIOM-MESH 0.12.0-dev.3 Build Notes

**Build:** `0.12.0-dev.3`

**Status:** supported development build on `main`; not a published release and
not production-promoted

**Updated:** 2026-08-12

This prerelease increment now includes a constrained machine-principal
foundation in addition to the bounded AXIOM One provenance work. Authenticated
`agent` principals are human-sponsored, deny-dominantly limited by finite
scopes, action and purpose ceilings, runtime identity, expiry, non-delegation,
and an enforced execution-time ceiling. The exact machine-authority digest is
bound through approval requests, plan provenance, capability claims, and
execution evidence. This is an authorization primitive, not an autonomous-agent
runtime, MCP/A2A endpoint, delegation system, or remote executor.

The same development line also records bounded AXIOM One provenance linking:
owner-scoped directional `derived-from`, `supports`, and `corrects` edges;
correction-without-replacement; human-readable edge display; self-link refusal;
and cross-principal denial evidence. It includes the preceding private-note,
tombstone, selective-export, human-explanation, and browser request-binding
work, but does not declare the planned `0.12.x` production-readiness work
complete.

## Current implementation

The current build contains the dependency-free four-service Node.js kernel:

- Gateway authenticates, validates, rate-limits, and exposes versioned
  user/operator APIs;
- Hypervisor composes deny-dominant policy, independently revalidates constrained
  agent authority, builds explicit plans, checks approvals, and issues
  short-lived single-use grants;
- Sandbox executes only the bounded operation named by a valid grant;
- Grid stores encrypted transactional state and signed hash-linked evidence.

The active production-candidate boundary additionally includes:

- human-sponsored constrained machine principals; legacy unconstrained `agent`
  registry entries, unknown/non-human sponsors, wildcard scope, administrator
  role, action/purpose escalation, expired profiles, and delegation fail closed;
- machine authority digests bound into exact approval requests, plans,
  capability claims, accepted-intent evidence, and result evidence;
- execution timeout reduced to the lower of ordinary policy and the machine
  principal's declared execution-time ceiling;
- backward-compatible least-privilege infrastructure `service` identities,
  with explicit opt-in to the constrained machine profile when needed;
- one-command exact source setup with prohibited lifecycle scripts and
  unchanged-lock proof;
- a versioned same-origin client contract for all 29 authenticated Gateway
  routes with hand-reviewed schema, explicit errors, bounded timeout/response,
  cancellation, stable idempotent replay, and no direct service access;
- an experimental loopback-only AXIOM One PWA foundation with a contract-only
  proxy, memory-only token, no remote assets/analytics/API cache, status and
  reversibly reviewed echo and four governed memory actions, exact
  explanations for all 20 stable Gateway outcomes and 37 current kernel events,
  approval-state distinctions, same-key uncertain-outcome recovery,
  owner-scoped private-note create/list, three fixed directional provenance
  links with correction-without-replacement, confirmation-bound tombstone,
  selective local export with explicit-only bundle reveal, cross-principal
  read/link/export/tombstone denial evidence, honest unavailable Share/Circles,
  raw evidence, and explicit non-promotion;
- a default-deny 40-route internal service policy, policy-derived active mTLS
  peer allowlists, loopback-only plaintext development URLs, four exact
  single-host unit-network segments, and protected required/forbidden-edge
  proof without claiming a multi-host deployment;
- mutually authenticated TLS 1.3 service transport with exact active-leaf
  pinning, offline rotation, and rollback;
- compact and independently restartable single-host service topologies;
- encrypted backup, restore, retention, credential rotation, data-key rotation,
  rollback, and recovery evidence;
- bounded telemetry, alert relay, SLO, request-pressure, dependency-loss,
  deny-egress, and incident-tabletop controls;
- authenticated node admission, Grid-signed discovery, deterministic scheduling
  reservations, expiry, quarantine, and restart persistence without remote
  execution;
- operator-approved encrypted causal exchange with signed partition/rejoin and
  conflict-convergence evidence without replicated consensus;
- signed deployment-independent secret and policy provider startup;
- fail-closed pilot evidence intake with exact build, image, custody, reviewer,
  and 13-envelope package contracts;
- a canonical threat model and independent-security-review findings intake;
- authenticated operator API and CLI.

The machine-readable capability registry remains authoritative. Documentation,
roadmaps, previews, laboratories, and synthetic fixtures cannot promote a
capability beyond its registry status. The machine-principal schema contains
future destination, rate, concurrency, request-size, and response-size fields;
those fields are not current live-enforcement claims until their Gateway/runtime
paths and evidence are completed.

## Current development programme

The canonical roadmap now advances three coordinated tracks.

### Trust and operations

The project is collecting authentic external evidence for one controlled
single-node pilot:

- dedicated pilot hardware and 30-day availability/capacity observation;
- pilot-owned secret, provider, backup-media, telemetry, and alert custody;
- scheduled restore and rotation under that custody;
- a named-roster facilitated incident exercise;
- dispositions for 32 deprecated-history credential candidates;
- an authentic independent security review and signed findings ledger;
- a complete reviewed pilot evidence package and separate promotion decision.

### Human utility and network activation

The current roadmap adds a parallel Phase 2H:

- **AXIOM One** — private personal agent, vault, approvals, and receipts;
- **AXIOM Verify** — independent local/static evidence verification;
- **AXIOM Circles** — invitation-based governed collaboration;
- **AXIOM Studio** — capsule, adapter, policy, and conformance tooling;
- **AXIOM Managed Node** — optional supported operations without platform data
  ownership.

The programme also specifies, without implementing or promoting:

- **AXIOM Link** as a provisional phone-relayed constrained personal endpoint;
- a **Personal Compute Fabric** for policy-first interchangeable local,
  managed, and provider inference; and
- a deterministic **Local Trust Plane** for credentials, policy, confirmation,
  budgets, one-use mandates, and external receipts.

The active `0.12.x` sequence is:

1. maintain the implemented Gateway client contract and complete the
   experimental AXIOM One browser/PWA human shell gates;
2. one bounded least-privilege AI provider adapter and useful personal
   workflows, followed by one immutable single-agent Runtime Capsule, a secret-
   free Personal Agent Pack, and transparent policy-first compute routing;
3. selective sharing, Verify, and invitation-based Circles.

The later architecture sequence adds a phone-relayed wearable prototype,
measured owner-local inference, synthetic/test-authority identity presentation,
and sandbox-value payment simulation before any bounded invitation-only pilot.
None is a current implementation claim.

The client contract is implemented and the browser shell plus its bounded
human-explanation and memory-lifecycle contracts are experimental. They do not
claim an authoritative pre-execution kernel plan, arbitrary relationship
authoring, direct edge deletion, hard deletion, restore, general consequential
approval interface, or safe download boundary. A supported browser product,
provider, workflows, sharing, Verify, and Circles remain roadmap and
requirements commitments, not implemented capability claims in this build.

### Machine interoperability substrate

The candidate Agent Runtime Adapter v1 contract is byte-pinned at version
`1.0.0`. The required `verify` workflow validates the contract and uploads a
commit-bound artifact from a 28-case synthetic reference drill covering signed
grants, mapping and grant bounds, revocation, cancellation, idempotency,
fallback, uncertain outcomes, tamper rejection, and secret exclusion. No
external runtime is loaded, no external effect is performed, and no capability
is promoted by this evidence.

The first machine-principal enforcement slice is implemented. The next sequence
is deliberately native-first:

1. complete the AXIOM Invocation Envelope over the existing Gateway semantics;
2. enforce remaining machine destination, rate, concurrency, request-size and
   response-size limits with negative tests and evidence;
3. provide policy-filtered capability discovery for machine principals;
4. bind credential references and typed artifacts without exposing secrets;
5. add MCP compatibility only after native authorization parity is proven;
6. add A2A, remote tasks, remote execution and attenuation-only delegation only
   behind their separate future gates.

Protocol compatibility must never create authority.

### Frontier incubation

Distributed authority, BFT, settlement, tokens, bridges, liquidity, autonomous
agents, task markets, regulated-domain systems, embodied systems,
arbitrary-code isolation, zk verification, and post-quantum migration may be
built in isolated laboratories.

Laboratory code remains disabled by default and separated from production
identities, secrets, user data, real value, and public authority. It cannot
change production or marketing status without the normal evidence gates.

The governing doctrine is:

> **Build broadly. Activate deliberately. Expose minimally. Promote only with evidence. Market only what is true.**

  autonomous runtime;

  non-delegation for machine-principal v1;

  purpose/action escalation, approval reuse and runtime-attestation overclaim;

  subordinate to the current registry;
- the `1.0.0-draft.1` Personal Compute Fabric and Local Trust Plane
  specification defines device, portable-agent, orchestration, routing,
  identity, authorization, and payment boundaries plus five documentation
  contracts and a seven-stage MVP sequence.

The runtime loads only the separately byte-pinned Agent Runtime Adapter
contract; it does not load the other four drafts. No MCP/A2A endpoint,
autonomous loop, remote execution, machine delegation, production credential,
live deployment, or production-promotion claim is created by this work.

## Documentation boundary

Every file under `docs/` on `main` is part of the supported current-build
documentation set and is checked by `mesh/src/check-docs.mjs`. The checker fails
if an unlisted document is added, a required document is removed, a local link
breaks, the security policies diverge, or required current-build content is
absent.

Historical release notes, generated APIs, installers, token and bridge plans,
old audits, research drafts, and superseded operational narratives belong only
to the locked deprecated documentation branch. They are not alternate
specifications for this build.

## Validation

The current build must pass:

```bash
npm run setup
```

The setup command installs both exact zero-dependency locks and runs the
clean-kernel and release verifiers. Protected GitHub verification additionally
runs kernel tests, container build and readiness, credential-history audit,
recovery, backup lifecycle, SLO, resilience, transport, service-unit,
node-scheduling, causal-exchange, telemetry, credential/data-key rotation,
provider conformance, pilot-verifier conformance, independent-review-verifier
conformance, incident tabletop, deny-egress checks, and CodeQL analysis.

Synthetic pilot and review fixtures prove verifier behavior only. They do not
claim a live pilot or independent review.

Release verification binds package and lock versions, the capability and
operator registries, supported documentation, deployment inputs, migrations,
rollback, and source boundaries. A development build is not promoted merely
because those checks pass.
