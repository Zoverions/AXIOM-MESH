## Version boundary

`0.12.0-dev.3` is the active development line after immutable candidate
`v0.11.0`. This file describes the current tree, including both registry-backed
implemented capabilities and built safety primitives that remain deliberately
production-unreachable.

The current line combines:

1. the hardened four-service authority/evidence kernel;
2. constrained human-sponsored machine principals, discovery, and terminal
   Grid-attested receipts;
3. stronger Grid continuity semantics with externally retainable anchors;
4. the experimental bounded AXIOM One owner-memory/provenance shell;
5. a production-unreachable evidence-first repository planning/resolver/outbox/
   draft-PR operator prototype; and
6. Agent Runtime Adapter v1 as a byte-pinned replaceable-runtime contract with
   synthetic reference conformance.

None of these changes alters the production decision. The build remains a
production candidate awaiting authentic pilot, custody, operational, and
independent-review evidence.

## Grid continuity clarification

Local Grid verification detects invalid signatures, altered records, gaps,
broken links, and disagreement with locally stored head/checkpoint state. Local
state alone cannot prove absence of a consistently removed suffix when matching
local head/checkpoint metadata is also rewritten.

`axiom-grid-continuity-anchor.v1` supplies the stronger retained-history
boundary when the anchor is stored outside `AXIOM_DATA_DIR` and the chain is
reverified from genesis. A valid anchor proves that current history equals or
extends the retained head through the **newest retained anchor**. It does not
cover later unanchored events and does not remove malicious host/root or active
Grid-signing-key compromise from the trust assumptions.

## Built repository-effect prototype — production-unreachable

The current source contains a complete evidence-first prototype for one narrow
future repository-document effect. It is intentionally not a current runnable
capability.

### Planning and resolver chain

The built core can:

1. create/verify a signed read-only repository plan against exact repository,
   base SHA, path, content, and lifetime constraints;
2. bind the plan to fresh executor eligibility and exact resolver/registry/
   policy/build/requester/target facts;
3. derive strict resolver admission facts;
4. require independent implementation-conformance and security-authority
   reviews;
5. package exactly one mapping addition without treating packaging as
   installation;
6. independently observe exact mapping application bytes without treating
   observation as execution authority;
7. re-run ordinary target policy, confirmation, and independent-approval gates;
8. bind the exact resolved input and authorization state to a prepared effect;
   and
9. source the named approval over authenticated Hypervisor -> Grid transport and
   atomically commit `approval.consumed` then `external.effect.prepared`.

Concurrent preparation tests prove only one durable prepared effect can survive
one-use approval consumption.

### Durable outbox and docs-only GitHub operator

The source also already contains the next layer:

- an external-effect outbox that requires durable preparation before operator
  invocation;
- restart/retry behavior that preserves a prepared effect across uncertainty;
- signed operator-receipt verification before `external.effect.completed` can
  be committed; and
- completion-commit failure behavior that requires replay from the same durable
  preparation rather than fabricating success.

The credential-isolated GitHub docs operator independently verifies Grid-durable
preparation **before any GitHub request**. It is fixed to
`Zoverions/AXIOM-MESH`, accepts only exact planned documentation paths/content,
uses a deterministic effect branch, and can create or recover an **open draft
pull request**. Tests cover stale `main`, extra/unplanned paths, content and
identity substitution, forged Grid proof, duplicate execution, service
isolation, and transport-loss/readback recovery.

It has no merge operation and reports `merge_performed: false` and
`base_branch_content_changed: false`. The prototype therefore proves a bounded
proposal path, not autonomous repository administration.

### Why it remains unavailable

Production reachability remains closed:

- `mesh/config/intent-remediation-executors.json` contains zero mappings;
- production `mesh/config/policy.json` has no
  `repository.docs.pull-request.create` action;
- no supported public/runtime route invokes the resolver/executor/operator
  chain;
- repository-operator credentials/egress are not part of the supported
  production deployment; and
- direct-main and merge authority are absent.

A future first mapping would be a new activation/promotion event requiring its
own policy/registry/runtime review, operator custody/egress controls, rollback,
negative tests, independent review, and explicit promotion decision.

## Agent Runtime Adapter v1 boundary

Agent Runtime Adapter v1 is byte-pinned at version `1.0.0`. The contract and
28-case synthetic reference drill cover signed grants, exact mapping/grant
bounds, one-use authorization, cancellation/revocation, idempotency, bounded
fallback, uncertain outcomes, tamper rejection, signed receipts, rollback, and
secret exclusion.

The architectural rule is explicit: a replaceable external runtime may plan or
coordinate work, but installation, runtime approval, a tool allowlist, or the
runtime's credential system cannot create a second authority path around
Gateway -> Hypervisor -> Sandbox -> Grid.

The reference loads no external runtime, resolves no production runtime
credential, opens no external runtime connection, reads no user file, performs
no external effect, and does not certify OpenClaw, Hermes, Agent Zero, MCP,
A2A, or another runtime.

## Current development programme

### Trust and operations

Still required for production promotion:

- dedicated pilot hardware and 30-day availability/capacity observation;
- pilot-owned secret/provider/workload-identity, backup-media, telemetry, and
  alert custody;
- scheduled restore and rotation under that custody;
- retained external Grid continuity-anchor cadence/custody;
- provider/custodian dispositions for all 32 deprecated-history credential
  candidates;
- named-roster facilitated incident response;
- authentic independent security review and findings ledger; and
- an authentic exact pilot evidence package plus separate promotion decision.

### Human utility/network activation

Continue AXIOM One security/accessibility/package work, one bounded AI provider,
useful personal workflows, selective sharing, AXIOM Verify, AXIOM Circles,
Studio, and Managed Node behind their individual gates.

The programme also specifies, without implementing or promoting, AXIOM Link as
a provisional phone-relayed constrained personal endpoint, a Personal Compute
Fabric for policy-first interchangeable local/managed/provider inference, and a
deterministic Local Trust Plane for credentials, policy, confirmation, budgets,
one-use mandates, and external receipts. The first implementation sequence adds
one immutable single-agent Runtime Capsule, a secret-free Personal Agent Pack,
and transparent policy-first routing before wearable, identity, or sandbox-
value payment prototypes.

### Machine/runtime work

Machine-principal authorization, discovery, receipts, the runtime-adapter
contract, and the repository draft-PR safety prototype now exist. Near-term work
therefore focuses on:

1. keeping repository-effect reachability closed while activation/custody/
   rollback review is completed;
2. selecting one maintained external runtime for a bounded read-only adapter;
3. proving native authorization, cancellation, idempotency, receipt, fallback,
   uncertainty, and direct-service-denial parity; and
4. deferring MCP/A2A, remote tasks, remote execution, and attenuation-only
   delegation to their own gates.

Protocol compatibility must never create authority.
