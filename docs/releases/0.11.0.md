# AXIOM-MESH 0.11.0 Release Notes

**Release type:** clean-room production candidate

**Verified source checkpoint:**
`1d318b481dc03858a4f46b63da05a395adbd7c6f`

**Clean public baseline:**
`4082d9349a949879e75fe6b0763e8408c5cfec77`

## Summary

Version 0.11 adds bounded-cardinality service telemetry, authenticated
OpenMetrics and operations reporting, aggregate dependency readiness,
production secret provisioning, file-backed secrets, a fail-closed
four-process supervisor, a host-side OTLP/Alertmanager relay, and a
digest-pinned hardened container candidate.

The supported runtime remains the dependency-free Node.js kernel in `mesh/`.

## Implemented capability highlights

- authenticated intent-to-evidence flow;
- deny-dominant policy and independent high-risk approval;
- encrypted Grid state and signed evidence;
- consent, capsule, memory, local accounting, governance, node, and storage
  records;
- signed scoped portability, staged imports, backup/restore, and offline
  causal sync;
- operator-approved online causal exchange with pinned Grid evidence,
  encrypted ordered staging, bounded retry, duplicate preflight, and explicit
  conflict convergence;
- deployment-independent startup from separate signed secret and policy
  providers with digest-pinned command artifacts, nonce-bound exact
  inventories, private generation cleanup, rotation proof, and invalid-signer
  fail-closed evidence;
- authenticated operator API and CLI;
- four-service readiness, operations report, OpenMetrics output, and bounded
  alerts;
- least-privilege Unix-socket telemetry collection with 68 fixed OTLP points,
  fixed Alertmanager labels, exact HTTPS origin routing, alert-reserved
  persistent queueing, bounded retry/dead-letter audit, and signed receipts;
- explicit external provisioning of service identities, API principals, and
  the data-protection key;
- offline service/API credential rotation and separate data-key re-encryption
  with authenticated rollback and signed disposable-host drill evidence;
- signed policy-derived encrypted-backup retention, recoverable quarantine,
  interruption recovery, and weekly exact-restore evidence;
- real host-mode four-process production drill.

## Container status

The Dockerfile and Compose policy are statically release-gated. The package
uses a digest-pinned Node.js 24.18.0 Alpine base, UID/GID 10001, a read-only
root filesystem, dropped capabilities, no-new-privileges, mounted secrets,
resource ceilings, bounded logs, and permission-restricted Unix-domain host
ingress. A post-baseline 0.11 hardening change uses
`network_mode: none`, fails startup when a non-loopback or IPv4/IPv6 default
route exists, and adds signed protected-CI ingress/egress evidence.
Pilot-platform repetition
and independent review remain promotion requirements.

The image build and composed readiness drill pass in
[GitHub run 30375390450](https://github.com/Zoverions/AXIOM-MESH/actions/runs/30375390450).
This implements the repeatable container package; it does not promote a live
deployment.

## Repository and compatibility change

The supported branch changes from legacy `Main` to clean-room lowercase
`main`. The public baseline has the same source tree as the verified checkpoint
but intentionally has no deprecated parents.

This is a source-history break, not a database-schema reset. The rolling
candidate advances Grid schema to version 10 for encrypted node discovery and
schedule records; the documented rollback compatibility rules continue to
apply.

## Security action

Any credential from deprecated Git history is permanently compromised and
must be replaced. Do not copy identities, private keys, API tokens, or data
keys from an older checkout.

After the baseline release, the supported line added a keyed 32-entry
deprecated-history inventory and protected supported-tip reuse gate. This
hardens the rolling 0.11 candidate without rewriting the published tag.
Repository revocation is recorded; external custodian/provider attestations
remain required before production promotion.

The rolling candidate also adds a machine-readable incident-response policy
and signed protected-CI tabletop. The exercise classifies a combined
credential and evidence-integrity scenario, enforces independent roles and
authority-reducing containment, and binds eleven verified operational control
artifacts from the same commit. It is automated candidate evidence, not a
named-roster pilot exercise or live-incident claim.

The rolling candidate adds a host-side telemetry relay without weakening the
container's deny-egress boundary. The dedicated scrape token is confined to
the two telemetry routes and participates in coordinated rotation. Protected
CI performs a real Unix-socket scrape, fixed-cardinality OTLP and Alertmanager
delivery, forced 503/429 retry, receipt audit, and Grid-signed evidence.
Pilot-owned HTTPS receivers, external credential custody, retention decisions,
and named-person acknowledgement remain promotion requirements.

The rolling candidate also adds a signed Linux request-pressure and
dependency-loss drill. It proves pre-reservation oversized-body rejection,
bounded concurrent rate limiting, dependency-aware degradation while the real
Sandbox process is suspended, fail-closed supervisor exit when Sandbox dies,
clean restart, and Grid-state preservation. Cgroup OOM/CPU, disk exhaustion,
pilot traffic, and orchestrator replacement remain pilot evidence.

The rolling candidate now requires mutually authenticated TLS 1.3 on every
internal service edge. Distinct Ed25519 leaves carry DNS and SPIFFE-style URI
identities; CA validation, exact active-leaf pinning, and signed-caller binding
reject missing, wrong, expired, drifted, or retired peers. Protected CI rotates
all leaves offline, restarts the real stack, rejects a retired CA-valid
Gateway leaf, executes an intent, restores the prior generation exactly, and
retains Grid-signed evidence. External CA custody and multi-host rollout
remain promotion gates.

The rolling candidate now also supports four independently restartable
single-host service units. Projection gives each unit exactly its own
application private key and TLS leaf, leaves durable state and the
data-protection key with Grid, and leaves the API registry with Gateway.
Signed host evidence kills and restarts Sandbox alone while proving survivor
continuity, readiness degradation/recovery, and Grid-state preservation.
Protected CI repeats the isolation check with four containers on an internal
deny-egress network. This is not a multi-host, automatic-failover, or live
production claim.

The rolling candidate also adds admitted-node v2 discovery and deterministic
placement reservations. Signed node statements bind HTTPS origin, failure
domain, roles, resource ceilings, capabilities, security profile, and lease.
Grid-signed discovery filters expired, quarantined, or unqualified nodes;
policy-controlled `node.schedule` commits only complete capacity-aware
placements and degrades them after quarantine or eligibility loss. Protected
CI rejects copied signing identities and resource exhaustion, simulates a
partition through missed renewal, and proves restart persistence in a signed
artifact. This does not launch remote work, verify endpoint health or resource
claims, solve global Sybil resistance, or claim federation.

The rolling candidate now also implements operator-approved online causal
exchange between two Gateway deployments for one matching owner. Each
direction pins the source Grid Ed25519 key, verifies signed event envelopes and
node bundles, persists an encrypted ordered queue, bounds retry and backlog,
and preflights an owner-scoped destination receipt before consuming approval.
The relay cannot approve its own work: every received bundle retains exact
one-use independent destination approval. Protected CI starts two real
production supervisors, injects a bidirectional partition, preserves cursors,
exposes the same concurrent heads after rejoin, converges through explicit
all-head resolution, and absorbs duplicate replay without approval. This is
not replicated Grid consensus, BFT, arbitrary federation, or independently
hosted WAN evidence.

The rolling candidate now also implements a deployment-independent provider
protocol for the existing production supervisor. Separate secret and policy
providers return short-lived, nonce-bound, exact resource inventories signed
by disjoint pinned Ed25519 identities. The broker pins executable and adapter
digests, bounds provider environment, runtime, and output, validates every
resource semantically, writes one private per-start generation, and removes
it at shutdown. Protected CI rotates the API registry and policy across a real
four-service restart, rejects the retired token, activates the new deny rule,
and proves that an invalid provider signer cannot start the runtime. The
included file adapter is conformance evidence, not a claim for any vendor
vault, cloud secret manager, workload identity, live refresh, or external
custody deployment.

The rolling candidate hardens concurrent release evidence generation with
atomic cross-process leases for aligned four-port loopback blocks. Every
real-stack drill holds its lease across startup, runtime, stopped maintenance,
and restart. Separate socket probes still reject external occupancy, while
regressions prove same-candidate serialization, non-overlap, idempotent
release, and safe reuse. This corrects an intermittent parallel-test
`EADDRINUSE` race; it is not a production networking claim.
