# AXIOM-MESH 0.12.0-dev.0 Build Notes

**Build:** `0.12.0-dev.0`

**Status:** supported development build on `main`; not a published release and
not production-promoted

**Updated:** 2026-07-29

## Version boundary

`v0.11.0` is the last immutable published production-candidate release. The
active source line advanced after that tag, so the package, capability
registry, operator surface, container tags, runtime evidence, and current
documentation now identify themselves as `0.12.0-dev.0`.

This file describes the current tree. It does not amend the contents or claims
of the published
[`v0.11.0`](https://github.com/Zoverions/AXIOM-MESH/releases/tag/v0.11.0)
release.

Unsupported documents and superseded implementation narratives were removed
from `main`. Their exact pre-cleanup state remains available on the locked,
read-only `deprecated/pre-0.12-documentation-corpus` branch. The older
pre-clean-room implementation remains preserved by the immutable
`archive/legacy-main-pre-clean-room-2026-05-21` tag.

## Current implementation

The current build contains the dependency-free four-service Node.js kernel:
Gateway authenticates and rate-limits callers, Hypervisor authorizes
deny-dominant plans, Sandbox executes the bounded built-in operation set, and
Grid stores encrypted state and signed hash-linked evidence.

The active production-candidate boundary additionally includes:

- mutually authenticated TLS 1.3 service transport with exact active-leaf
  pinning and offline rotation;
- compact and independently restartable service-unit topologies;
- encrypted backup, restore, retention, credential rotation, data-key
  rotation, rollback, and recovery evidence;
- bounded telemetry, SLO, resilience, deny-egress, and incident-tabletop
  controls;
- authenticated node admission, discovery, deterministic scheduling, and
  local resource leases without authorizing remote execution;
- operator-approved encrypted causal exchange with signed partition/rejoin
  evidence, without claiming replicated consensus;
- signed deployment-independent secret and policy provider startup with
  separate trust identities, exact resource inventories, pinned provider
  artifacts, private immutable runtime generations, and restart-bound
  rotation.
- fail-closed pilot evidence intake with a separately supplied policy trust
  anchor, five distinct reviewer keys, exact build/image and 30-day/SLO/
  custody binding, an exact offline package of 13 canonical role-signed
  v2 evidence envelopes with exact type-specific detail contracts, and an
  output that cannot promote production.
- a canonical current-build threat model and independent-security-review
  intake with a separately supplied policy trust anchor, exact
  build/scope/artifact binding, distinct reviewer and exception approver,
  recomputed findings, independently verified critical/high remediation,
  bounded lesser-risk exceptions, and an explicit non-promotion result.

The machine-readable capability registry remains the authority for runnable
claims. Documentation cannot promote a capability beyond its registry status.

## Documentation boundary

Every file under `docs/` on `main` is part of the supported current-build
documentation set and is checked by `mesh/src/check-docs.mjs`. The checker
fails if an unlisted document is added, a required document is removed, a local
link breaks, the security policies diverge, or required current-build content
is absent.

Historical release notes, generated APIs, installers, token and bridge plans,
old audits, research drafts, and superseded operational narratives belong only
to the locked deprecated documentation branch. They are not alternate
specifications for this build.

## Validation

The current build must pass:

```bash
npm run check
npm run release:verify
```

Protected GitHub verification additionally runs the clean kernel tests,
container build and readiness drill, credential-history audit, signed recovery
and rotation drills, deny-egress and independent-unit checks, causal exchange,
provider conformance, incident tabletop, pilot dossier verifier conformance,
exact pilot evidence package verifier conformance, independent-security-review
verifier conformance, and CodeQL analysis. Both pilot intake artifacts are
explicitly synthetic; the package artifact also proves dossier-inconsistent
detail rejection. The review artifact explicitly declares that no independent
review was performed. None claims a live pilot or production promotion.

Release verification binds package and lock versions, the capability and
operator registries, supported documentation, deployment inputs, migrations,
and source boundary. A development build is not promoted merely because those
checks pass.

## Non-claims

`0.12.0-dev.0` does not claim:

- a live public or customer production deployment;
- provider custody, live provider refresh, or a completed external
  secret-manager pilot;
- remote task execution, federation, BFT or replicated consensus;
- arbitrary untrusted-code isolation;
- external AI, messaging, storage, chain, identity, or payment adapters;
- regulatory certification or independent security approval;
- completed pilot capacity, availability, recovery, incident, or external
  revocation evidence;
- an authentic accepted pilot evidence package or a production promotion
  decision.

Those boundaries remain promotion gates in the readiness tracker and roadmap.
