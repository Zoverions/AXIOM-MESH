# AXIOM Host Node Zero — Shelf Node Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first real AXIOM-controlled Ubuntu 24.04 LTS x86_64 Shelf Node: a recoverable, default-deny, locally sovereign host that runs the current AXIOM-MESH runtime and independently cycles locally cached book covers on a vertical display.

**Architecture:** Ubuntu remains responsible for kernel, firmware, drivers, bootloader, and base packages. AXIOM adds a signed/digest-bound host-install planner and executor, Host Guardian, service/network hardening, runtime release slots, node identity/enrollment evidence, and an isolated offline display workload. The display is a sibling of the Mesh runtime under host supervision: Mesh failure, Internet loss, or failed enrollment must not prevent the last-known-good local display playlist from running.

**Tech Stack:** Ubuntu 24.04 LTS x86_64; Node.js 24.x within the repository's supported range; systemd; cgroup v2; nftables; AppArmor; Docker Engine/Compose using the existing AXIOM candidate-production topology; Xorg + `feh` + `xrandr` for the first lightweight display renderer; Ed25519; existing AXIOM canonical JSON/digest utilities; Node built-in test runner.

**Spec:** `docs/superpowers/specs/2026-09-03-node-zero-shelf-node-design.md`

## Global Constraints

- Canonical first host base: **Ubuntu 24.04 LTS x86_64**.
- Node Zero is an AXIOM host profile on Ubuntu, not a forked Linux distribution.
- Installation grants **no** Mesh, governance, application, agent, storage, compute, or external-effect authority.
- Mesh enrollment is an explicit separate step.
- No public listener is enabled by installation alone.
- AXIOM service/workload egress is deny-by-default; host-maintenance networking is a separate authority lane.
- Consequential AXIOM effects continue through `Gateway -> Hypervisor -> Sandbox -> Grid`.
- Runtime services use dedicated unprivileged identities; install-time privilege is temporary and separate.
- `/var/lib/axiom-secrets` is never readable by the display workload and secrets never enter repository content, release images, shell history, receipts, or telemetry.
- The first physical fail-safe invariant is: loss of Internet, all remote AXIOM services, enrollment, Host Guardian, or the local Mesh runtime must not prevent booting and cycling the last-known-good book-cover set.
- A failed or incompatible AXIOM update must leave the previous verified generation active or enter a local recovery state; partial/unverified generations never activate.
- Node Zero v0 does not claim Secure Boot/TPM attestation, general remote execution, relay, distributed compute, storage-provider service, governance participation, personal-agent memory, or production capability promotion.
- No production signing private key is committed or generated by normal installation code.
- Every security/custody mutation emits a non-secret, digest-bound receipt.
- Unit tests must not mutate the developer host. Privileged effects are tested against temporary roots/fakes first, then in disposable Ubuntu VMs, then on Node Zero hardware.

## Hardware Pilot Success Criteria

The first hardware pilot succeeds when all of these statements are evidenced, not merely intended:

1. The machine boots unattended into the vertical book-cover display.
2. The active playlist is entirely local and validates against its manifest.
3. Pulling the network connection does not interrupt the display.
4. Killing the AXIOM Mesh runtime does not interrupt the display.
5. Killing Host Guardian does not interrupt the display.
6. The Mesh runtime itself still enforces its current production isolation/deny-egress contract.
7. No AXIOM-created public listener exists.
8. The display identity cannot read Mesh secrets or Grid state.
9. A tampered update is rejected before activation.
10. A readiness-failing but rollback-compatible runtime returns to the previous verified generation.
11. Reboot restores both the display and local AXIOM services automatically.
12. The machine can create a signed, bounded enrollment-request artifact without automatically enrolling itself or requesting shared resource roles.
13. Exact installation/update/recovery receipts contain no secrets.
14. The evidence record names the exact source revision, release, host-profile digest, installed package versions, and hardware facts.

Passing these criteria establishes **Node Zero pilot evidence**. It does not by itself promote AXIOM-MESH to a generally supported production operating-system distribution or federated infrastructure network.
