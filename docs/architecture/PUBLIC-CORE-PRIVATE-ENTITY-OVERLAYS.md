# Public Core / Private Entity Overlays

**Status:** architecture boundary; no runtime implementation claim

**Updated:** 2026-09-01

## Rule

The public repository contains reusable entity substrate and sterile public packs. User-specific life history, private relationships, legal/court material, health/financial records, credentials, private identities/personas, and other sensitive grounding are installed later as private overlays and are not required in Git.

## Public core

Public core may contain:

- Blank Egg / entity foundation contracts;
- layer/stack contracts and validators;
- agency provenance, consent, authority, protest, privacy, resource, recovery, and verification machinery;
- synthetic fixtures;
- intentionally public constitutional/judgment/domain/skill packs;
- schemas, conformance tests, and threat models.

Public core MUST NOT require a founder biography, personal legal history, private correspondence, credentials, or private user corpus.

## Optional public layers

A public layer is an inspectable, versioned artifact that can be installed, rejected, forked, suspended, or superseded. A public layer may express a judgment constitution, worldview, domain workflow, disposition, culture, skill, or presentation system.

Installation does not create effect authority.

## Private overlays

Private overlays may include:

- personal grounding;
- private memories;
- relationship state;
- private notes/drafts;
- private books or unpublished writings;
- legal/court material;
- health/financial records;
- private personas;
- private embeddings/adapters derived from user data.

Private overlays should use independently governed vault/pack/context mechanisms. Their content does not enter public fixtures, logs, schemas, or commits.

## Relationship to Personal Agent Pack v2

Personal Agent Pack v2 is one owner-private continuity and recovery vehicle layered above the neutral foundation. It can reference vaults, correction/evaluation ledgers, preferences, routing policy, presentation state, and optional personalized model artifacts without becoming the underlying entity foundation or authority root.

## Installation path

```text
Blank Egg foundation
 -> optional public layers
 -> optional relationship layers
 -> private Sovereign Vaults / owner overlays
 -> optional personalized artifacts under explicit authorization
 -> runtime/model placement through the Intelligence Fabric
```

Every stage preserves normal Mesh authority, privacy, resource, and recovery rules.

## Non-claims

This boundary does not prove that an underlying model has no learned bias or personal information from its original training. It guarantees only that AXIOM's public composition layer does not require or embed the user's private overlay.
