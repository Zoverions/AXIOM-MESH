# Roadmap Extension — Human, Entity, and Societal Fabric

**Status:** subordinate future-compatible roadmap extension; no capability promotion

**Updated:** 2026-09-01

**Parent:** `docs/ROADMAP.md`

## Objective

Extend the current human-product/runtime programme into a durable substrate for persistent entities, adaptive compute, dual human/agent capability surfaces, Mirror Institutions, lifelong deliberation/learning, and scalable information circulation while preserving the current authority/evidence kernel.

## Phase HES-0 — Documentation and contract alignment

- publish integrated architecture specs;
- map human-facing names to stable machine capability families;
- preserve existing agency/resource specs;
- add implementation queue and plan;
- keep all new capability statuses non-runnable until code/tests exist.

**Exit:** architecture and queue are internally consistent and current claims remain unchanged.

## Phase HES-1 — Human sovereignty + agency provenance

- implement semantic validators/schemas for agency provenance, human sovereign baseline, relational deliberation;
- add protest/stop-right negative tests;
- add capability-surface registry draft;
- prove no authority/runtime activation.

**Exit:** human/counterpart/worker/joint provenance remains distinguishable end-to-end in sterile tests.

## Phase HES-2 — Resource governance + persistent orientation

- Resource Envelope/Observation contracts;
- sovereignty reserve and priority classes;
- deterministic pressure states;
- model-independent stop/pause/cancel;
- dormant obligations and trigger router;
- bounded background cognition;
- host inventory and compute qualification.

**Exit:** background work cannot starve human control and durable orientation survives cognition shutdown/runtime replacement.

## Phase HES-3 — Intelligence Fabric + first embodiment

- intelligence endpoint inventory/profile;
- local/remote inference topology distinction;
- cost/privacy/latency routing;
- one bounded native/API cognition adapter;
- one narrow specialist;
- runtime replacement proof;
- recovery bundle/dry-run restore.

**Exit:** same persistent entity resumes across two cognition routes without authority expansion or provider lock-in.

## Phase HES-4 — Studio/Lab + deployment profiles

- modular Studio shell;
- Deployment, Entity, Circle, Governance, Institution, Network modules;
- Lab experiment/scenario envelopes;
- Windows coexistence, dedicated Linux, offline/recovery, and later Android edge profiles;
- Verify integration.

**Exit:** Studio produces inert, verifiable compositions and deployment plans; Lab can attack them before activation.

## Phase HES-5 — Circles, Mirror Institutions, lifelong feedback

- Circle Core v0;
- institutional digital twins/mirrors;
- affected-party/competence/authority separation;
- simulation and outcome comparison;
- education/competency evidence bridge;
- privacy and anti-surveillance gates.

**Exit:** at least one low-consequence consenting pilot demonstrates parallel deliberation without mirror authority leakage.

## Phase HES-6 — Information metabolism

- claim/provenance graph;
- semantic deduplication and correction propagation;
- attention/subscription/digest controls;
- narrow-first inference pipeline;
- bounded network propagation;
- value-of-information scheduling;
- multi-dimensional contribution/outcome research with essential-floor safeguards.

**Exit:** information can remain discoverable without continuous push/reprocessing, and corrections/independent corroboration remain attributable.

## Phase HES-7 — Network/cloud/edge expansion

- provider-neutral node profiles;
- encrypted remote backup;
- controlled local/remote causal exchange;
- multiple independent providers/failure domains;
- edge handheld/wearable capability maps;
- disconnected local Mesh operation;
- long-history and soak evidence.

**Exit:** provider/device loss degrades capability, not identity or sovereign control.

## Promotion gates

No phase completion by documentation alone changes `mesh/config/capabilities.json`. Promotion requires code, tests, negative/adversarial evidence, recovery, security review, accessibility/human evidence where relevant, and explicit lifecycle updates.
