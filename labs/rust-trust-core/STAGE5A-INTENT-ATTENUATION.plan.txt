Rust Trust-Core Stage 5A — Verified-Grant Intent Attenuation Conformance
Date: 2026-09-06
Status: approved design; implementation gate
Base main: ad8c0bd92f74f328c1c7e86c3d6e2723119defb3

GOAL

Add a laboratory-only Rust candidate for the pure verified-grant/bound-intent attenuation predicate and prove exact behavioral parity with the supported Node implementation in mesh/src/lib/authority-composition-guard.mjs. Node remains authoritative. Stage 5A does not issue grants, verify signatures, consume capabilities, evaluate history/composition restrictions, call a runtime service, or exercise effects.

ARCHITECTURE

The supported Node function verifyIntentAttenuation(grant, intent) remains the executable oracle. A language-neutral TSV fixture admits only bounded ASCII scope identifiers so JavaScript and Rust ordering semantics are identical inside the evidence domain. The Rust laboratory parses the same rows, rejects malformed/unverified/unbound inputs, evaluates four set-containment checks, and exposes only the resulting boolean checks. Differential tests invoke the real Node oracle as a subprocess and compare the five booleans exactly.

No code is added under trust-core/rust/. The Rust candidate remains under labs/rust-trust-core/ and has no production Cargo manifest, binary, FFI, WASM, service, subprocess call from supported runtime code, capability registration, Gateway route, credential access, state access, network access, or effect path.

GLOBAL CONSTRAINTS

1. Node remains authoritative and is executed directly by the oracle.
2. The protected authority path remains Gateway -> Hypervisor -> Sandbox -> Grid.
3. Stage 5A may only answer whether a bound intent is a subset of an already independently verified grant.
4. Stage 5A may not create, sign, verify, consume, persist, revoke, delegate, or exercise authority.
5. No production Node call site may import or invoke the Rust candidate.
6. No file under trust-core/rust/ may change in Stage 5A.
7. Rust dependencies remain empty; unsafe remains forbidden.
8. Unknown or malformed fixture data fails closed; no coercion or truncation.
9. Exact-head acceptance is invalidated by any later commit.
10. Cryptographic verification and full authority-composition evaluation are deferred to separate later gates.

FIXTURE CONTRACT

Path: labs/rust-trust-core/fixtures/intent-attenuation-v0.tsv

Header columns, in order:
case_id
grant_verified
intent_bound
grant_actions
grant_purposes
grant_destinations
grant_resources
intent_actions
intent_purposes
intent_destinations
intent_resources

Rows are tab-separated. Set fields are comma-separated. Empty text means an empty set.

Scope identifiers are restricted in the evidence grammar to:
[A-Za-z0-9][A-Za-z0-9_.:/-]{0,191}

Each set:
- contains at most 128 items;
- must already be ASCII-lexicographically sorted;
- must contain no duplicates;
- is compared by exact string equality.

The scope-token restriction is a laboratory transport grammar, not a claim that the supported Node function accepts only these strings.

Valid differential rows require grant_verified=true and intent_bound=true. They may evaluate either valid=true or valid=false depending on containment.

Oracle output columns:
case_id
valid
actions
purposes
destinations
resources

All result fields use literal true/false. Output order is fixed. Duplicate output case IDs fail closed in the Rust harness.

INVALID CONTRACT

Path: labs/rust-trust-core/fixtures/intent-attenuation-v0-invalid.tsv
Header: case_id<TAB>encoded_row

The invalid corpus must cover at minimum:
- wrong TSV column count;
- malformed case_id;
- malformed grant_verified boolean;
- malformed intent_bound boolean;
- unverified grant;
- unbound intent;
- unsorted grant set;
- duplicate grant set member;
- unsorted intent set;
- duplicate intent set member;
- malformed scope identifier;
- overlong scope identifier.

For malformed grammar, both decoders must reject. For syntactically valid unverified/unbound cases, the Node oracle and Rust candidate must both fail closed before returning an attenuation result.

GENERATED CONFORMANCE

The Rust differential test deterministically generates 512 additional rows and sends the exact same serialized fixture text through the Node oracle and Rust parser/evaluator.

The generator is test-only input generation and is not an authority implementation.

Use xorshift32 with fixed seed 0x53544135 and explicit wrapping unsigned 32-bit transitions:
state ^= state << 13
state ^= state >> 17
state ^= state << 5

Generated evidence:
- 256 subset cases: all four intent dimensions are subsets of their grant dimensions and must remain valid;
- 128 single-dimension widening cases: exactly one of actions/purposes/destinations/resources contains one member absent from the grant and must be invalid, with only that corresponding check false;
- 128 monotonic attenuation descendants derived from valid subset cases by removing admitted intent members; they must remain valid.

Each generated result must match the real Node oracle exactly. The monotonic property is additionally asserted directly: removing requested scope from a valid intent cannot turn attenuation invalid.
